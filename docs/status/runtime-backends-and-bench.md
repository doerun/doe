## Admission blockers

- No external application has completed material-outcome, accepted execution
  ownership, independent repeat use, and release admission together. The
  declared program matrix does not inherit credit from compatibility receipts.
- Application latency, peak GPU memory, concurrency, crash/hang behavior,
  physical device loss, and leak evidence must satisfy the promoted workload's
  release requirements. Explicit device destruction is a bounded lifecycle test.
- Clean installation must be qualified on each supported host/backend tuple.
  Local tarball qualification does not establish registry publication, npm
  authentication, or independent customer reproduction.
- The production signer registry remains a separate admission requirement.
  Self-consistent unsigned or untrusted signed receipts cannot establish trust.
- CTS coverage must complete the policy-defined required query scope before
  supporting conformance language. Subset runs remain diagnostic.
- Fawn remains experimental distribution work. Browser smoke and local builds
  do not establish a release-class archive or replace native/package evidence.
  Current browser obligations are routed through [`../browser-lane.md`](../browser-lane.md).
- Recomposition evidence must bind the frozen candidate, matching native ABI,
  backend-local physical host, and approved source digest. The current owner is
  [`runtime-architecture-audit.md`](runtime-architecture-audit.md).
- Performance remains advisory under `config/gates.json`; claim-bearing rows
  still require same-work, timing-scope, reliability, and suspicious-win checks.
