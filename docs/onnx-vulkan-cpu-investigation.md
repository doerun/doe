# ONNX Vulkan CPU investigation contract

This additive diagnostic contract follows the
[completed ONNX Vulkan campaign](onnx-vulkan-campaign-contract.md). Its negative
application-performance decision and historical manifest remain unchanged.
[Policy](../config/onnx-vulkan-cpu-investigation.json) freezes sampling controls,
owner admission and any subsequent candidate's application metric, material gain,
regression bounds, independent processes and stopping rule. The
[report](../reports/benchmarks/amd-vulkan/20261008-onnx-vulkan-cpu-attribution/README.md)
closes the investigation without an admitted general correction.

## Evidence boundary

The ordinary SqueezeNet application retains its source, model, inputs, numerical
oracle and pinned ONNX consumer. Both native arms retain their original library
bytes and validation request. A diagnostic application header and private bridge
add observation only. Recovery, failed initialization, reuse and disabling/oracle
controls qualify this specific instrumentation. General callback conformance and
interruption of submitted work remain open; pre-execution cancellation is not
submitted-work interruption.

CPU sampling uses a main-thread CPU timer, a reserved signal, bounded stack reads
and fixed writes. The implementation follows Linux
[timer semantics](https://man7.org/linux/man-pages/man2/timer_create.2.html) and
[signal-handler restrictions](https://man7.org/linux/man-pages/man7/signal-safety.7.html).
Independent thread/process clocks bound coverage. Delayed deliveries can bias
sampled locations, so overruns remain unassigned. Candidate frames and stripped
symbol labels cannot establish complete call stacks. No projected removal of
required work counts as an optimization or a qualified prediction.

An owner must satisfy the frozen share and independently supported predicted
application gain against both retained Doe and source-built Dawn before a general
correction is admitted. Any candidate then requires safety qualification and
independent uninstrumented application confirmation. The report's approximate
whole-site removal projections support the stopping review, not a proof that
all possible optimizations are impossible. No production change was selected.

## Schema migration

[The evidence schema](../config/onnx-vulkan-cpu-evidence.schema.json) adds typed
build, run, profile, decision and manifest records. The separate
[policy schema](../config/onnx-vulkan-cpu-investigation.schema.json) covers frozen
thresholds. Existing campaign artifacts and schemas retain their meaning.

Run identities bind qualification, selected application/bridge, environment and
raw observations. Final sample records contain unsigned little-endian fields for
PC, thread, overrun, API site, candidate-frame count, candidate addresses and
selected registers. Exploratory prototype layouts remain explicit in their
receipts or custody scope; they are not admitted by the final semantic verifier.
Profiles retain executable load segments, mappings, resolved locations, optional
inline frames, candidate caller/leaf relations, call-site populations and clocks.
Decisions separate diagnostic admission from performance correction and claims.

Manifests bind compressed and decoded bytes, current tooling, native source
snapshots, historical-report identity and optional ignored executable custody.
The verifier independently reconstructs the admitted population and decision.
Earlier prototypes with missing executed builder snapshots remain exploratory.
Intrusive timing controls and unfavorable observations remain retained. These
artifacts authorize no runtime support expansion or public speed claim.

Compiler work remains conditional on a new concrete reproduction. Browser
transformations remain closed; browser replacement, Metal and D3D12 remain
outside this investigation. No successor campaign is automatically selected.
