# Bounded ONNX Vulkan CPU attribution

The [decision](decision.json) admits the final diagnostic sampling cohort and
stops without an admitted general correction, runtime patch or performance claim.
Original independent processes reproduce the completed SqueezeNet campaign's CPU
loss. Binding creation, compute recording, retirement and common driver work
contribute. Approximate sampled-site removal projections do not independently
justify the frozen predicted advantage over retained Doe and source-built Dawn.
This does not prove that every possible optimization is impossible.

[Policy](policy.json) froze diagnostic overhead, CPU coverage and owner admission
before the complete measurement. Any candidate would require safety followed by
independent uninstrumented application confirmation under its declared CPU metric,
material-gain threshold and regression bounds. No candidate was executed.

## Qualified boundary

The ordinary upstream SqueezeNet application keeps its prepared source, model,
inputs, pinned ONNX core/provider, numerical requirements and behavior. Every
invocation checks its full output against the independent reference; CPU fallback
remains disabled. Both backends retain the previously qualified native binaries,
context selection and validation request. Each manages its own preparation and
synchronization. Processes have independent HOME/XDG/Mesa caches and explicit
warmup; this investigation does not create a cold-cache performance claim.

The final private diagnostic application and bridge retain executed builder and
sampler source snapshots. Recovery, failed initialization, successful reuse,
physical Vulkan identity, actual native call counts, cleanup and library/oracle
failure controls pass. Caller sampling and timer-disabled controls pass the
frozen overhead rule. Main-thread/process CPU clocks separately bound coverage.
The [historical campaign](../20261005-onnx-vulkan-campaign/README.md) and its original
negative performance decision remain unchanged.

## Retained limitations

Timer overruns remain unassigned and can bias sampled location shares. Frame
pointers provide bounded caller candidates, not complete certified unwinds.
Inline frames are symbolizer observations. Stripped-library labels may identify
nearby exported functions; they do not demonstrate CPU operator fallback.
Executable ELF load segments, rather than file offsets alone, determine PC
attribution.

The earlier intrusive per-call clock cohort fails comparative admission and
remains retained. Earlier sampler prototypes are exploratory; some executed
builder sources were not retained. Their output is not promoted by the final
source-bound cohort. General callback/future conformance, interruption of
submitted work, other hosts and upstream adoption remain open. Pre-execution
cancellation/reuse does not establish submitted-work interruption.

The investigation leaves production runtime and compiler code unchanged. Browser
transformations remain closed. Metal, D3D12 and browser switching remain deferred;
no successor campaign is automatically selected.
